# День 1. Введение, архитектура, требования

## Задача простыми словами
Банки получают жалобы клиентов. Проект собирает жалобы из открытого источника (CFPB, США), складывает в хранилище,
сопоставляет с размером банков (FDIC) и отвечает на вопросы бизнеса. Данные американские, архитектура не зависит от страны
и подходит любому банку.

## Бизнес-вопросы
1. По каким продуктам и компаниям жалоб больше всего и как это меняется по неделям и месяцам?
2. Как быстро компании отвечают (`timely`) и чем закрывают жалобы (объяснение, компенсация)?
3. У каких банков жалоб больше при том же размере (жалоб на 1 млрд USD активов)?
4. Сколько обращений остаётся «в работе» и как давно они открыты (по потоку изменений CDC: Debezium + Kafka).

Ограничение данных: сумм в жалобах нет, только счётчики, доли и сроки.

## Объём и ограничения (из слов ментора)
- Через Airflow не больше 100 тыс. строк на запуск. Запуск = один день: банки около 780 строк, бюро около 21 тыс.
- Историю (2,7 млн строк) Airflow за один запуск не грузит: запуск = один день, агрегаты считают SQL в Postgres (DAG витрин) и dbt.
- Кредитные бюро и взыскание долгов вынесены в отдельный контур: низкая ценность для анализа банка и объём в разы больше.

## Архитектура
```
CFPB API ──curl──> Airflow: cfpb_final / cfpb_bureau_pipeline (1 запуск = 1 день)
FDIC API ────────> Airflow: fdic_financials_pipeline (раз в месяц, все кварталы)
                          |
                          v
 CSV: FRED DFF, dim_company, company_bank_map --> тот же DAG (stg -> ods)

 DAG final_tabyldieva_pipeline:  stg --> ods --> проверки --TriggerDagRun (та же дата)-->
 DAG final_tabyldieva_datamart:  витрины dm_* --> проверки --> ClickHouse (tabyldieva.dm_complaints_daily)

 PostgreSQL:  stg  -->  ods  -->  datamart                dbt: модели + тесты в tabyldieva_dbt
  (как пришло)  (типы, ключ)  (витрины)
      |
  etl_load_log (журнал)

 CDC: tabyldieva.complaint_cases --Debezium--> Kafka --sink--> tabyldieva_ods.ods_complaint_cases

 Airflow: cfpb_final (история 2023-2026), cfpb_resync (раз в неделю: находит дни, где stg расходится с API)
```

## Принципы
Идемпотентность (повтор дня даёт тот же результат), громкие ошибки (пустой день, чужая дата, лишнее поле,
расхождение с API, продукт вне списка не пропускаются молча), секреты только в переменных окружения.

## Честные оговорки для комиссии
- Данные американские; сумм в жалобах нет.
- Свежие недели недосчитаны: CFPB публикует жалобы с опозданием и иногда снимает их.
- Только около 43% жалоб относятся к банкам из FDIC; метрика «жалоб на 1 млрд активов» грубая.
- CDC работает на имитированной таблице обращений `complaint_cases`: у API CFPB нет собственного потока изменений, статусы меняет скрипт.
  Механика (журнал WAL, Debezium, Kafka, приёмник) настоящая, данные об изменениях синтетические.
- Ставка ФРС показана как контекст дня; причинной связи с числом жалоб проект не утверждает.
