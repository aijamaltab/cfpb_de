# Паспорт источников данных

Проект: хранилище жалоб клиентов на банки США (CFPB). Автор: Айжамал Табылдиева, логин `tabyldieva`.

Всего шесть источников: два API (CFPB, FDIC), три CSV (ставка ФРС и два справочника) и «база сайта» для CDC. Требование
«не меньше двух CSV (событие с датой и справочник) и одного API» выполнено.

## 1. Жалобы потребителей CFPB (API)
| Вопрос | Ответ |
|---|---|
| Тип | API |
| Откуда | `GET https://www.consumerfinance.gov/data-research/consumer-complaints/search/api/v1/`, параметры `date_received_min` и `date_received_max` (один день), `product` (одно значение за запрос), `size`, `sort`, `no_aggs=true`. Страницы листаются курсором `search_after` |
| Доступ | ключ не нужен, лицензия CC0. Сайт отвечает 403 на python-requests, поэтому запросы идут через `curl` (`ingestion/cfpb_http.py`). Таймаут 30 с, 3 повтора |
| Роль | события: жалоба с датой получения |
| Поля | 15 полей, среди них `complaint_id`, `date_received`, `product`, `sub_product`, `issue`, `company`, `state`, `company_response`, `timely`, `submitted_via`. Пример ответа: `docs/api_sample.json` |
| Как меняется | новые жалобы каждый день; прошлые дни дописываются задним числом (жалоба публикуется после ответа компании или через 15 дней); у жалоб в работе меняется `company_response` |
| Объём | 8 банковских продуктов, в среднем около 780 жалоб в день; загружено 869 218 жалоб за 1 октября 2023 — 13 октября 2026 |
| Что может сломаться | свежие недели неполные (лечит ежедневная перезагрузка окна, DAG `final_tabyldieva_refresh`); пустой ответ с кодом 200, новое или пропавшее поле, чужая дата в ответе — загрузка падает и в stg ничего не пишется; 403 от защиты сайта |
| Куда | `tabyldieva_stg.stg_cfpb_complaints` → `tabyldieva_ods.ods_complaints` |

Продукты (написание как в API): Credit card; Checking or savings account; Mortgage; Money transfer, virtual currency, or money
service; Vehicle loan or lease; Payday loan, title loan, personal loan, or advance loan; Student loan; Prepaid card. Список
лежит в `PRODUCTS` в `ingestion/load_cfpb.py`.

## 2. Показатели банков FDIC (API)
| Вопрос | Ответ |
|---|---|
| Тип | API |
| Откуда | `GET https://api.fdic.gov/banks/financials`, `filters=REPDTE:<конец квартала>`, `fields=CERT,REPDTE,ASSET,DEP,NETINC,ROA,ROE,EQ,NUMEMP`, `limit=5000`, `offset` |
| Доступ | ключ не нужен. Таймаут 60 с, 3 повтора |
| Роль | справочник размера банка по кварталам, нужен для метрики «жалоб на 1 млрд USD активов» |
| Поля | `CERT` (номер банка), `REPDTE` (конец квартала), `ASSET`, `DEP`, `NETINC`, `ROA`, `ROE`, `EQ`, `NUMEMP`; суммы в тысячах USD |
| Как меняется | раз в квартал добавляется новый квартал; пересматривает ли FDIC старые отчёты, я не проверяла, поэтому перезагружаю все кварталы целиком |
| Объём | 14 кварталов (Q1 2023 — Q2 2026), около 4,5 тыс. банков в квартале, около 63,8 тыс. строк |
| Что может сломаться | число строк не совпало с `meta.total` или в квартале меньше 3000 банков — загрузка падает; последний квартал ещё не опубликован (допускается только в конце ряда) |
| Куда | `tabyldieva_stg.stg_fdic_financials` → `tabyldieva_ods.ods_fdic_financials` |

## 3. Ставка ФРС FRED DFF (CSV, событие с датой)
| Вопрос | Ответ |
|---|---|
| Тип | файл |
| Откуда | выгрузка ряда DFF с сайта FRED: `curl -sS -m 60 "https://fred.stlouisfed.org/graph/fredgraph.csv?id=DFF&cosd=2023-10-01" -o data/fred/DFF.csv`. DAG читает файл с диска; если файл не дотягивает до даты запуска, задача пробует его докачать |
| Доступ | ключ не нужен |
| Роль | события: одна строка на календарный день |
| Поля | `observation_date`, `DFF` (ставка, % годовых) |
| Как меняется | новая строка каждый день, включая выходные; старые значения не правятся. За дату `ds` DAG берёт из файла одну строку |
| Объём | одна строка в сутки, около 20 КБ |
| Что может сломаться | FRED публикует значение с задержкой 1–3 дня: тогда в ods переносится последняя известная ставка с пометкой `is_carried = true` (не дальше 14 дней); `.` вместо числа превращается в NULL; другой заголовок файла — загрузка падает |
| Куда | `tabyldieva_stg.stg_fred_dff` → `tabyldieva_ods.ods_fred_dff` → колонка `fed_funds_rate` витрины `dm_complaints_daily` |

## 4. Справочник компаний (CSV)
| Вопрос | Ответ |
|---|---|
| Тип | файл `data/ref/dim_company.csv` |
| Откуда | составила сама по данным проекта: 60 компаний с наибольшим числом жалоб, это 83,2% всех жалоб |
| Роль | справочник |
| Поля | `company_cfpb` (название как в жалобах, ключ), `canonical_name`, `company_type` (одно из 18 значений: `big_bank`, `regional_bank`, `fintech_payments`, `credit_bureau` и др.), `fdic_candidate`, `note` |
| Как меняется | правится вручную, когда в топе появляется новая компания |
| Объём | 60 строк |
| Что может сломаться | неизвестный `company_type` — загрузка падает; название не совпало с жалобами — компания получит тип `other` |
| Куда | `stg_dim_company` → `ods_dim_company` → колонка `company_type` витрины `dm_company_month` |

## 5. Привязка компаний к банкам FDIC (CSV)
| Вопрос | Ответ |
|---|---|
| Тип | файл `data/ref/company_bank_map.csv` |
| Откуда | составила сама: номера `cert` подобрала по справочнику FDIC |
| Роль | справочник, мост между жалобами и размером банка |
| Поля | `company_cfpb`, `cert`, `bank_name`, `note` |
| Как меняется | правится вручную |
| Объём | 25 строк: 24 компании → 25 банков; покрывает около 43% жалоб |
| Что может сломаться | слияние банков (номер исчезает из FDIC, не проверялось); компании нет в `dim_company` — загрузка падает |
| Куда | `stg_company_bank_map` → `ods_company_bank` → витрина `dm_bank_size_quarter` |

## 6. «База сайта»: обращения `tabyldieva.complaint_cases` (источник CDC)
| Вопрос | Ответ |
|---|---|
| Тип | таблица OLTP-базы |
| Откуда | схема `tabyldieva` на том же Postgres 16. Читается не запросами, а журналом изменений: Debezium → Kafka → sink-коннектор |
| Доступ | коннектор работает под ролью владельца таблицы; пароль вводится при запуске в переменную `CDC_PASSWORD`, в файлах его нет. Публикацию и слот создают скрипты `cdc/sql/` |
| Роль | сущность: текущее состояние обращения |
| Поля | `complaint_id`, `product`, `company`, `state`, `status` (`in_progress`, `closed_explanation`, `closed_relief`, `closed_other`), `timely`, `received_at`, `updated_at` |
| Как меняется | статус обращения меняется в любой момент |
| Объём | 28 240 обращений, дальше поток изменений |
| Что может сломаться | забытый слот репликации копит журнал на диске (`cdc/sql/05_slot_monitor.sql`, `99a_drop_slot.sql`); без `wal_level = logical` поток не читается; без `REPLICA IDENTITY FULL` в событии нет старых значений |
| Куда | `tabyldieva_ods.ods_complaint_cases` → модель dbt `dm_open_cases` |

У открытого API CFPB нет потока изменений. Таблицу `complaint_cases` я сделала как имитацию системы обработки обращений банка:
номера, продукты и компании взяты из реальных жалоб, а статусы меняет скрипт `cdc/sql/04_change_scenario.sql`. Механика CDC
настоящая, изменения синтетические.

## Что пробовала и не взяла
- Население США (Census): сайт недоступен со стенда, и данные годовые.
- FDIC `/institutions`, открытые данные ЦБ Узбекистана, рейтинг жалоб Бразилии (BCB): попробовала, в проект не вошли.
- Жалобы на кредитные бюро и коллекторов из того же API: загрузила для сравнения за июль–сентябрь 2026 (1,9 млн жалоб), потом удалила. На вопросы о банках они не отвечают, а места занимали вдвое больше всех жалоб на банки.
